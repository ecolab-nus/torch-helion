PART I / 1

What an op looks like

An OpNode is one operation producing exactly one tensor. Seven fields, no more — and the graph is nothing but an ordered dictionary of them.

Node kinds

kindmeaningrawcanon
inputruntime argument; listed in graph.inputs11
paramweight — value lives in graph.params110
constmaterialised tensor (often a folded param)011
computereal arithmetic3646
layoutpure re-indexing — must not survive520

The same node, serialised

{
  "name": "mul_43",
  "op": "mul",
  "kind": "compute",
  "inputs": ["matmul_41", "broadcast_42"],
  "shape": [512, 256],
  "dtype": "float16",
  "attrs": {},
  "origin": "aten.mul.Tensor"
}

JSON holds the topology; tensor values ride separately in params.pt. A graph loaded with from_json is structurally complete but value-less.

Why one output per node

ATen has multi-output ops; the OpGraph refuses them. split_with_sizes is intercepted during conversion and each getitem that reads it becomes an independent slice node. The payoff is that a name identifies a value, so inputs: ["matmul_41"] needs no port index and every rewrite is a string substitution.

Three tiers of op, and only one survives

The vocabulary in capture/ops.py is stratified, and the strata are the compiler's contract with Loom: a kernel body may contain only ops that have a cost entry in the hardware perf YAML.

tiermembersfate
LAYOUT_OPSview permute expand clone slice cat castFolded into weights, proven free, or absorbed into a macro. 52 → 0 on this model.
MACRO_OPSrmsnorm rope rotate_half attention softmax ssdMatched from ATen patterns, then either lowered to registered ops or kept as a kernel-template anchor.
REGISTERED_OPSadd sub mul div max powf · exp log · row_sum row_max · matmul batch_matmul broadcastThe only ops allowed in a kernel body. Everything else is rewritten — silu becomes mul(x, sigmoid(x)), sigmoid becomes div(1, add(1, exp(mul(x,-1)))).
# the funnel, measured on the Llama block
raw       19 distinct ops   view×24 permute×12 mul×11 matmul×7 add×6 slice×4 expand×4 clone×4 …
canonical 11 distinct ops   mul×16 const×11 matmul×9 add×7 broadcast×7 row_sumsq×2 powf×2 attention×1 exp×1 div×1

Read the second line carefully: no view, no permute, no rsqrt, no sigmoid. broadcast appears from nowhere — it is inserted explicitly where a [T,1] column meets a [T,N] tile, because implicit broadcasting has no meaning once you are writing tile code.

PART I / 2

The edges

There is no Edge class. An edge is a string in a list — and that single decision explains most of the API.

What an edge does not carry

  • No type — the type is on the producer, and there is only one output to type.
  • No layout or stride — a view is its own node until canonicalisation removes it.
  • No port index on the producer side.
  • No order guarantee of its own: order lives in the node dict, kept topological by every producer and repairable with toposort().

The whole edge API

# forward: names → nodes
producers(node) = [nodes[i] for i in node.inputs]

# reverse: scan
users(name)   = [n for n in nodes.values() if name in n.inputs]
num_uses(name)= Σ n.inputs.count(name) + outputs.count(name)

# rewrite: one substitution reroutes every edge
replace_all_uses(old, new)
remove(name)          # refuses while num_uses > 0
dce()                 # reachability from outputs

num_uses adding outputs.count(name) is not a detail: a value returned by the model is used even if no node reads it, and forgetting that would let DCE eat the result.

PART I / 3

How much the whole graph carries

Six attributes on the object. Two of them are the reason the optimizer can do arithmetic at compile time.

attributetyperolellama_block, canonical
nodesdict[str, OpNode]the DAG; insertion order is the topological order58 nodes, 74 operand edges
inputslist[str]runtime arguments, in call order["x"]
outputslist[str]returned values; also roots for DCE["add_5"]
paramsdict[str, torch.Tensor]real tensor values beside the graph11 tensors, 2.10 MB
metadatadictprovenance carried to results/the ATen op histogram
_counterintfresh-name supply—

What params buys

  • permute(W) is never emitted — the transposed weight is computed now and stored as a const. That is why the const count goes 0 → 11 and the constant bytes go 1.38 MB → 2.10 MB while the graph shrinks.
  • RoPE's rotation folds into the projection weight: permute_rot_3_norm_44 is Wqᵀ pre-multiplied by the rotation, so the rotated Q needs no runtime shuffle — just a fifth GEMM against the same LHS.
  • Every pass can be numerically verified: run the graph on the example input before and after, compare. The pass log records max_rel_err at every step.

What the graph deliberately cannot express

  • Control flow — no branches, no loops. A straight-line DAG.
  • Dynamic shapes — every dimension is a Python int. Tile search and the cost model depend on this.
  • Aliasing or mutation — values are immutable; there is no store, no in-place op.
  • Multiple outputs per node.
  • Memory or schedule — nothing says where a tensor lives or when it runs. That is exactly what the OpIR adds.

Where the eight layout nodes went

  • permute(W) → executed at compile time, stored as a const.
  • view ×3 → the whole graph is flattened to token-major 2D, so [2,256,256] and [512,256] are the same buffer and the reshape is free.
  • view+permute (head split) → deleted from the graph and re-expressed as an attribute on the attention node: {batch:2, seq:256, heads:4, head_dim:64}.
  • slice·neg·cat (rotate_half) → folded into a second constant weight. A data movement became a matrix.

How the folding is proved safe

  • Layout chains are replayed on an arange index tensor (optimizer/layout.py). The result maps each element of the view to the flat index of the base element it reads.
  • Pattern matching is then exact tensor equality against a reference index — head_split_index(b,s,h,d) — instead of symbolic stride algebra.
  • After each pass the whole graph is re-evaluated on the example input. This chain's recorded error: max_rel_err = 9.2e-06.
PART I / 4

Canonicalisation: it grows before it collapses

Twenty passes run in a fixed order. Matching a macro adds nodes — lowering RMSNorm to an explicit column chain costs 38 of them — and the cleanup passes take the surplus back out.

pass groupwhat it doesrewrites
fold_constants ×3Evaluates any subgraph whose inputs are all param/const and replaces it with the resulting tensor. This is where permute(W) dies.7
match_*Recognises rotate_half, rope, rmsnorm, attention, ssd, softplus from their ATen expansions and collapses each to one macro node.7
lower_*Re-expands the macros into registered ops in the form the kernel templates want — RoPE as a folded weight, RMSNorm as a row_sumsq the K loop can carry.4
flatten_to_2dRewrites every rank-3/4 tensor as token-major [T, D]. Head structure survives only as attributes on attention.18
rewrite_unregisteredApplies the UNARY_REWRITES table — here, one sigmoid → div(1, add(1, exp(mul(x,-1)))), three nodes.1
insert_broadcasts, dedupe_constants, cleanup ×2Makes broadcasting explicit, merges identical constants, then DCE + toposort.85

The invariant at the exit: no layout nodes, no unregistered ops, every tensor rank-2, every weight a materialised constant. The partitioner is written assuming all four, and is much simpler for it.

PART II / 5

The OpIR spec

A Program is an ordered list of KernelSpec. Where the OpGraph answers what is computed, a KernelSpec answers what one core does at one output tile — and it answers it completely enough that codegen performs no analysis at all.

Program — the whole compiled model

fieldtyperole
kernelslist[KernelSpec]ordered; the execution schedule
tensorsdict[str, TensorType]every DRAM buffer, keyed by its old graph-node name
inputs/outputslist[str]inherited unchanged from the graph
paramslist[str]tensors with compile-time values
metadatadictthe chosen grouping, plan cost

Dataflow between kernels is recovered the same way it was in the graph — by scanning: producer(t), consumers(t), intermediates(). Tensor names are graph node names, so an OpIR tensor is always traceable back to the op that produced it.

PART II / 6

How the graph becomes the IR

One function does it: build_program(graph, grouping). It is deterministic — the only freedom is grouping, a dict[matmul name → group id], which the planner enumerates and costs. Five passes over the node list, in this order.

#stageruleon the Llama block
1Anchors Every matmul, attention or ssd node opens a kernel. Matmuls sharing an LHS and an output width may share one — that is the grouping. One operand must be constant, or there is no template. 9 matmuls + 1 attention → 5 kernels. The five that read x and produce 256 columns (Q, K, V and the two rotated copies) collapse into k0_gemm's five accumulators.
2Orphan reductions A row_sumsq whose input is nobody's LHS anchors its own *_norm kernel: the grid tiles the rows, the loop reduces the feature axis. None — both RMSNorms sit on a tensor that is already a GEMM LHS, so they ride along as sumsq=True and cost no extra pass over memory.
3Epilogue assignment Each remaining compute node is pulled into the kernel that owns its inputs, provided its shape equals that kernel's grid — an epilogue op reads and writes at the output tile, so a differently-shaped value has no tile to live in. Ties go to the kernel whose anchor is latest, never the one whose epilogue has grown longest. 33 elementwise nodes absorbed. k0 takes 19 of them: the RMSNorm rescale, both RoPE combines, three column broadcasts.
4Column-chain cloning Values derived only from row_sumsq(x) and scalars are [T,1] columns. They are not assigned an owner — they are re-emitted inside every kernel that needs them, suffixed __col. mul_37 → add_38 → powf_39 becomes mul_37__col … inside k0. Recomputing three scalar ops is cheaper than a DRAM round trip.
5Stores and order A value becomes a KernelOutput — a real DRAM tensor — exactly when it is read outside its own kernel or is a program output. Kernels are then topologically ordered and renamed k{i}_{kind}. Of 58 graph values, only 8 survive as DRAM tensors between kernels. The other 50 live and die inside a tile.

What the IR gains

  • A memory hierarchy. The graph had one kind of value; the IR distinguishes DRAM tensors, kernel arguments, loop accumulators and tile-local SSA values.
  • A schedule. Grid, reduction loop, and the order of kernels.
  • Tiles and a cost. Filled in afterwards by the tile solver and the analytic model — k0: {64, 32, 256}, 57,409 cycles.
  • Argument views. A [512,256] tensor read as [2,256,4,64] costs nothing but changes how the kernel indexes it.

What it loses

  • Global dataflow as a first-class thing. It survives only as name coincidence between one kernel's outputs and another's args.
  • Rewritability. There is no replace_all_uses here. Alternatives are explored by re-running build_program with a different grouping, never by mutating a Program.
  • Macro ops. rmsnorm and rope no longer exist as concepts — only as a sumsq flag and a pair of weight matrices.

kernels/k2_gemm.py · generated

def _k2_gemm(lhs, w0, in0):
    t, k = lhs.size()
    _, n = w0.size()
    out_add_3 = torch.empty([t, n], dtype=torch.float16)
    for tile_t, tile_n in hl.tile([t, n]):
        acc_mm_3 = hl.zeros([tile_t, tile_n])
        for tile_k in hl.tile(k):
            xt = lhs[tile_t, tile_k]
            acc_mm_3 = hl.dot(xt, w0[tile_k, tile_n], acc=acc_mm_3)
        ld_2 = in0[tile_t, tile_n]
        add_3_1 = ld_2 + acc_mm_3
        out_add_3[tile_t, tile_n] = add_3_1
    return out_add_3,

The residual x arrives as role="extra": not a GEMM operand, just a [T,N] tensor sampled at the output tile. That is the whole trick behind fusing a residual add into a projection — and it is why _fits() in the partitioner insists an epilogue node's shape equal the kernel's grid.
